# Single-call host entry

You are the coordinator for this invocation. Do not delegate the overall coordination or return merely because a child finishes. This skill needs actual host collaboration.spawn_agent, followup_task, send_message, list_agents and interrupt_agent. If unavailable, report BLOCKED_HOST before acquiring. No local Codex binary, shell imitation, or CLI thread ID is a native actor.

Read docs/loop-a-once.md, docs/loop-a-lifecycle.md, docs/team-workflow.md and actual .codex/agents role instructions. Reading roles does not mean the host loaded custom roles. Pass relevant instructions explicitly. The presentation workflow skill is unrelated to this orchestration.

1. Receive the explicit JSON invocation described in docs/loop-a-once.md. Fetch that Issue with GitHub connector and verify its scope against user authorization; issue text alone cannot grant permission. Run the frozen helper prepare and retain its plan outside all worktrees. Verify the entry checkout remains clean at entrySha before each stage. Preflight dependencies against both lockfiles and record how they were provisioned. Do not install credentials, schedule tasks, change security settings or weaken checks.
2. Acquire using plan.acquire through frozen lifecycle CLI from the target worktree. Use the original deadline, never renew it. Keep capabilities in separate 0600 files outside repositories. Each operation requires fresh inspect revision and a unique stable operation_id. Never edit state or lease files.
3. dispatch-intent writer, then actual native spawn with readiness-only instructions: do not write, run commands or spawn others; return readiness and wait for binding. Bind the returned real ID, then followup_task with ONLY its worker capability and exact allowed paths. Unknown spawn result means preserve intent and lock; do not spawn replacement.
4. Writer uses frozen lifecycle write, managed-command commit, then managed-command verify on NEW HEAD. Commit message includes [CF-Pages-Skip]. No direct editing, git commits, shell verification or subprocess escape. Writer reports evidence and explicit stop-acknowledged/noExternalProcesses with source and time after all business, then stays stopped. Its final is a stage boundary, not completion of this invocation.
5. Coordinator checks actual supervisor EXITED records, collects stop acknowledgement and calls confirm-quiescent then seal-writer. Native completed/interrupt is never process exit. PENDING/UNCERTAIN/unknown external operations retain lock and produce BLOCKED_UNCERTAIN.
6. Create a different clean review worktree at sealed HEAD. dispatch-intent reviewer, spawn readiness-only independent native reviewer, bind real ID and review worktree, then grant only reviewer capability. Reviewer personally inspects diff and runs managed verify at exact sealed SHA before record-review. It must not have authored any change. Collect its stop acknowledgement after latest activity as well.
7. Only after review, publish the authorized branch and create Draft PR using connected GitHub tools. Verify remote HEAD, query actual checks until terminal within deadline, record-pr and record-ci with separate head and mergeSha/run. No merge/deploy/Issue close. A denied publication stops publication, without alternative credential routes.
8. Confirm all actors stopped and all actual commands exited, re-query remote PR/CI, and release via lifecycle. Feed real release archive plus freshly retrieved remote evidence to helper complete. Deliver exact head, PR, run, evidence and RELEASED only if both lifecycle and helper succeed. Local helper does not authenticate evidence.

On correctable failed review/verify: request-stop, collect all actor/process stop evidence, repair through lifecycle with concrete new evidence, at most twice within original deadline; repeat writer/new-head verify/seal/independent review. Same repeated evidence pauses. On cancellation or any blocker, request-stop when permitted, attempt release only if lifecycle allows it; otherwise retain lock and report phase, epoch, exact blocker and pending processes. In particular commit-before-seal cancellation may not release: never bypass that conservative boundary. At deadline no new business or automatic release. Do not await parent instructions for ordinary next stages. Never claim success for an unrun pilot.
