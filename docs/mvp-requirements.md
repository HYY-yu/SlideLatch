# MVP 需求

状态：草案 v0.3；更新：2026-10-31。本文定义功能与技术验收；商业实验见 [用户验证](validation-plan.md)，方案状态见 [产品决策](decisions.md)。

## 1. 产品目标

让报告团队的模板负责人不学习 DSL，也能把已有 PPT 配置为可重复生成的模板：上传原稿，在预览中确认可修改对象及规则，试生成，通过后导出模板和 AI 使用包。后续由外部 AI 生成符合合同的内容，再通过确定性生成器产出可编辑 PPTX。

首轮目标：一份真实模板完成一次配置，生成两份不同内容，记录配置、生成及修订耗时。

同一版本复用配置，设计、节点或合同变化后发布新版本。外部 AI 生成标准内容 JSON，生成器检查结构、长度和容量；视觉效果通过边界试填与原生验收确认。

## 2. 目标用户与定位

### 2.1 第一批目标用户

小型咨询、研究和报告交付团队，已有稳定设计，定期按客户或报告期重复生成相似 PPT。

| 角色 | 任务 | 产品提供的价值 |
| --- | --- | --- |
| 模板负责人：分析师、设计师或懂自动化的同事 | 配置并维护团队模板 | 减少学习标记语法和排查模板错误的成本 |
| 内容使用者：顾问、项目经理、分析师 | 用新内容生成报告 | 复用既有设计，在 PowerPoint 中继续编辑 |
| 付费决策者：团队或工作室负责人 | 控制交付时间和质量 | 用重复生成节省的时间评估接入成本 |

招募条件：近期有重复交付任务，能描述当前流程与修订成本，愿意提供脱敏模板和两组内容。

第一版不面向偶尔做 PPT 的个人，也不承担大企业 SSO、复杂审批、CRM 集成和全自动报表任务。

### 2.2 差异化假设

对外定位：“保留你的 PPT 设计，确认一次可修改区域，让不同 AI 按规则填充，生成可编辑的 PowerPoint。”

| 维度 | 本产品拟提供 | 需要证明的结果 |
| --- | --- | --- |
| 原对象打标 | 选中既有对象，确认语义与规则，无需重画透明占位形状 | 比现有手工配置流程更容易完成 |
| 明确合同 | 字段说明、文字长度、列表容量、固定区域、可定位错误 | 用户能独立修复主要输入错误 |
| 可迁移 | 模板、合同、示例和可独立运行的生成器 | 离开网页与供应商账号后仍能生成 |
| 一次接入 | 同一版本配置后反复使用 | 用户主动完成第二次生成 |

差异需通过试点验证；竞品能力与来源见 [竞品研究](competitor-research.md)。

## 3. 交付形态与范围

首版建议采用本地单用户网页工作台与生成器，文件、草稿和任务保存在用户设备。运行形态在 M0 定案，远程托管与多人协作后置。

界面及错误信息支持中文和英文；内容语言与界面语言独立。首轮兼容目标是桌面 Microsoft PowerPoint 2019+，以最终文件实际验收为准；不承诺 Keynote、Google Slides 或旧版 Office 完全一致。

初始验收边界建议为不超过 20 页、20 MB 的普通 `.pptx`，属于待性能验证的产品上限，配置集中管理。拒绝加密文件、宏文件、损坏包和超限输入；不自动转换这些文件。

### 3.1 第一版动态组件

| 对象 | 第一版范围 | 越界处理 |
| --- | --- | --- |
| 页面级文本 | 标题、正文、标签；纯文本与可见字符长度合同 | 复杂富文本编辑后置；存在混排时提示替换可能改变局部样式 |
| 页面级图片 | 已有图片槽位，用户上传 PNG/JPEG，按模板框居中裁剪 | 仅支持已有图片对象 |
| 固定列表 | 已存在、能明确对应 Item 的文本列表或 Group 列表 | 用户确认 Item 与组件映射；歧义不得自动发布 |
| 有界变长列表 | 已预制到上限、结构一致的 Group Item，可删除多余项 | 不自动把任意散落对象重组成列表，不超出预制上限复制 |
| 表格、图表、图标、背景、序号 | 本版不提供新增动态合同的编辑入口 | 保持为固定内容；已含此类 DSL 的上传文件明确标记为超出本版动态能力 |
| SmartArt、OLE、视频、复杂组合 | 不提供动态修改 | 能原样保留则作为固定内容；无法确认安全保留时阻断对应模板发布 |

固定内容须通过实际文件测试。除变长列表外，未标记对象保持位置、结构与样式。当前生成器会删除备注并可能裁剪悬空动画，导入报告需列出影响并由用户确认；需要保留备注的模板须先补齐支持。

### 3.2 后置能力

完整 PPT 在线编辑器、字体/颜色/素材编辑和重新设计、自动重组任意 Group、AI 生图、内置聊天、多供应商模型接入、外部数据连接器、定时生成、团队权限、模板商城、订阅计费、无限容量列表、自动修复所有不兼容文件。

## 4. 用户流程

### 4.1 首次配置模板

1. **上传与检查。** 用户上传经授权的 PPTX。系统保存原文件并计算哈希，检查包结构、页面、字体、外部关系及支持情况，生成准备副本。原件不覆盖。
2. **预览与对象盘点。** 左侧页面缩略图、中间 SVG 页面画布、右侧对象与规则面板。节点语义内容可编辑，样式只读；支持位置与尺寸调整。用户点击对象或从对象树选择；旋转、组合、遮挡对象必须支持从树定位。
3. **生成标记建议。** 程序识别文本、图片和重复 Group 的结构，提出可修改对象及字段用途建议，标明依据和待确认项。默认所有内容固定；建议不直接生效。
4. **用户确认。** 选择固定或可修改，填写字段显示名、用途、文本最小/最大长度；列表确认 Item 边界、同构组件和数量范围。系统给出可修改区域总览，全部确认后才能编译。
5. **编译与修复。** 在副本的节点名和必要元数据中写入 DSL，编译 Manifest、Schema 和 lock。错误定位到页码、对象和规则，修复后重编译。不得用静默忽略绕过错误。
6. **试填。** 使用正常内容和边界内容测试；图片由用户绑定本地资产。渲染结果供用户检查，结构检查通过与视觉确认分别展示。
7. **发布模板版本。** 通过编译、试生成和人工预览确认后，冻结版本并导出模板包与 AI 使用包。试填覆盖代表性最长中英文与最大密度列表。

### 4.2 重复生成

1. 用户选择已发布模板版本。第一版默认原页序和一页一实例；允许保留选定页、明确排序，不开放自动挑选版式和整页多次复制。
2. 导出当前页面计划对应的内容 Schema、字段说明、示例及提示词；用户交给自己选择的 AI，并提供本次资料。
3. AI 输出内容 JSON。用户导入文件或粘贴 JSON；系统展示缺字段、额外字段、长度和列表容量错误，以及对应页面和对象。
4. 用户局部修改，或把修复报告交回 AI。第一版不自动调用收费模型修复，不机械截断文字。
5. 用户通过资源面板为图片槽位绑定本地文件；同页/列表内以明确槽位确认，不由 AI 输出任意路径或 URL。
6. 内容通过校验后，程序绑定资产并执行最终校验，调用生成器和包检查。失败保留输入、错误与可恢复状态，不提供失败文件作为正式结果。
7. 展示结果、质量报告和文件哈希，用户下载并在 PowerPoint 中继续编辑。开始第二次生成时复用模板合同，不重新打标。

### 4.3 修改模板

合同修改在草稿副本进行，发布新版本，旧版本与历史任务保持可复现。重新上传即使只改变样式，也要核对节点映射、重编译和重试填，不自动套用旧 Manifest。第一版用变更摘要和人工重新确认，不承诺任意改版的自动迁移。

## 5. 功能需求与验收

全部 P0 为首轮可交付 MVP；P1 为用户需求成立后再做。

| 编号 | 级别 | 功能 | 最低验收标准 |
| --- | --- | --- | --- |
| F01 | P0 | 导入与兼容报告 | 保留源文件；损坏、加密、超限和不支持动态对象均有明确处理；报告固定内容和已知输出变化 |
| F02 | P0 | 页面渲染与对象选中 | 逐页缩略图与 SVG 画布共用渲染；原对象 ID 映射一致，支持对象树、组合与子对象选择 |
| F03 | P0 | 结构建议与人工标记 | 无外部 AI 也能人工完成全部 P0 打标；自动建议可接受、拒绝和修正；未确认不能发布 |
| F04 | P0 | 标记与布局面板 | 文本范围和列表容量合法；允许修改节点语义内容、标签、位置和宽高，支持拖动/缩放与撤销；样式只读，导出向原 PPTX 写回内容与标记/布局补丁 |
| F05 | P0 | 标记写回与编译 | 只修改准备副本；节点定位稳定；输出完整 Manifest、两种 Schema、lint 与 lock |
| F06 | P0 | 用户页面计划 | 1–3 页模板、无目录模板可合法生成；未选择页不进入输出；不强制五类页面 |
| F07 | P0 | AI 使用包 | 两种外部 AI 的人工试用均可产出可校验或可定位修复的内容；不含资产路径和敏感样例 |
| F08 | P0 | 导入、报错与局部修复 | 错误包含稳定 code、路径、页码、对象、实际值与期望；修复不能改动未请求字段 |
| F09 | P0 | 资源绑定与输出 | AI 内容与本地资产分离；缺图片阻断；生成与 verify 均通过才可下载正式输出 |
| F10 | P0 | 边界试填与发布 | 覆盖最长文本、列表最少/最多项；提示渲染字体差异；记录用户预览确认和版本 |
| F11 | P0 | 可迁移模板包 | 在一个干净的受支持本地环境，断开产品服务并无平台密钥时，安装锁定依赖后能校验、生成和验证 |
| F12 | P0 | 本地草稿及任务恢复 | 重启可恢复确认进度；失败任务可重试计算阶段；旧输出不冒充本次成功结果 |
| F13 | P0 | 中英文与可观测性 | UI、错误和说明有中英文；日志可定位阶段和对象，不默认记录完整客户内容 |
| F14 | P1 | AI 语义建议 | 在用户明确选择资料范围和模型后提交；展示建议而非直接修改，失败可回人工流程 |
| F15 | P1 | 动态表格与图表 | 开放已有底层数据合同并完成端到端映射、工作簿和原生编辑验收 |
| F16 | P1 | 自动版本迁移和协作 | 节点 diff、映射迁移、团队权限和共享模板；不得与 P0 基础版本绑定混淆 |

P0 辅助能力包括本地结构识别、规则检查与可视化确认。若用户无法接受人工确认成本，调整 F14 语义 AI 建议的优先级。

## 6. 现有 PPT-DSL 能力盘点

基于现有 Skill、源码与测试目录的静态盘点；开发前核对版本并运行相关测试。

| 能力 | 当前基础 | 复用方式与新增工作 |
| --- | --- | --- |
| 节点 DSL 和 locator | `src/dsl/`、`src/types.ts`；shapeId/path、slidePath | 复用定位与语法；新增可视化标记模型到 DSL 的双向映射 |
| 模板编译 | `src/compile-template.ts`，输出模板、Manifest、schema、lint、lock | 复用管线；新增未标记文件盘点和写回准备副本 |
| 文本和列表合同 | `src/validation.ts`、`src/schema.ts`、Group/list 测试 | 复用可见字符、组件一致性和容量规则；新增 UI、用户字段元数据和错误本地化 |
| 内容与资产分离 | `--content-only` 与最终输入校验 | 保留两阶段；新增资源 ID 到本地安全路径的绑定层 |
| 内容语义样例 | `sampleContent` 进入 Manifest/schema description | 复用语义机制；导出前让用户确认或替换原稿样例，避免泄露旧客户内容 |
| 原模板生成 | `src/generate-deck.ts`、`src/pptx/` | 复用原页和母版、按 locator 替换；新增任务封装与通用页面计划适配 |
| 图片填充 | `image-fill.test.ts` 与生成器裁剪逻辑 | 复用 PNG/JPEG 裁剪；新增预览和本地资产选择 |
| 原生数据组件 | `data-components.test.ts`、表格/图表类型合同 | 保留底层能力与回归；MVP UI 不开放动态数据组件 |
| 富文本、图标和共享背景 | 现有富文本、SVG、背景合同及测试 | 不删除既有能力；本产品 P0 不暴露相应编辑入口 |
| 模板哈希和版本锁 | `src/template-contract.ts`、模板 lock | 复用完整性检查；新增不可变发布版本、草稿和任务引用 |
| 输出包检查 | `src/verify-deck.ts`、`package-qa.test.ts` | 必须复用；不以包合法代替视觉与数值正确 |
| 页面预览及对象选择 | 当前 Skill 未提供产品级界面 | 新增渲染方案、坐标转换、对象树、高亮与原生对象映射 |
| 独立分发 | 当前为 Skill 内 Node/TypeScript CLI 项目 | 新增运行包、锁定依赖、入口说明、兼容矩阵与分发许可核对 |

### 6.1 必须改造的流程耦合

`src/lint.ts` 明确要求模板覆盖封面、目录、章节过渡、内容、结尾五类。`src/validation.ts` 要求首封面、第二页唯一目录、3–6 章、章节内容对应及目录数量一致。`src/types.ts` 中 `PageType` 也限定这五类。它们是实际约束，修改用户提示词不足以支持短报告。

拟新增显式策略 `deckPolicy`，值至少包括既有 `structured` 和产品使用的 `template-fill`；这是待实现设计，不是现有 CLI 参数。

| 项目 | structured 保持现状 | template-fill 新合同 |
| --- | --- | --- |
| 页面类型和布局 | 保留五类和章节规则 | 页类型可选语义标签；无目录和短 Deck 合法 |
| 页面计划 | 由大纲选择模板页 | 用户选择顺序，冻结为本次计划 |
| 内容 Schema | 按既有模板/大纲使用 | 按本次页面计划派生；AI 不修改 templateId 或页序 |
| 编译和输入校验 | 原有行为、旧调用默认不变 | 只放松 Deck 组织规则，保留所有节点与包结构 gate |
| 编号 | 章节和 Item 编号 | P0 不新增页面编号槽位；列表已有编号由程序处理 |
| 最终 verify | 共享包结构验证 | 所有页面策略共用完整包验证 |

策略写入 Manifest、lock、Schema 和任务快照；旧文件缺少策略按 structured 处理。新建产品模板显式写 template-fill，禁止自动将校验失败的旧模板降级放行。编译、validate、generate 对策略处理一致，schema 与后端不得各自推断不同默认值。

策略改动落在生成器仓库，同步更新 SKILL.md、DeckInput、程序 gate、类型、lint/validation/schema、CLI 与回归测试。

## 7. 数据与导出合同

### 7.1 四层数据

1. **源文件层**：用户原文件和哈希，不覆盖。
2. **标记草稿层**：页、对象 locator、固定/动态状态、语义字段、范围、列表映射与人工确认。
3. **发布模板层**：准备副本、完整 runtime Manifest、内容 Schema、最终输入 Schema、lock、策略和 runtime 版本。
4. **生成任务层**：模板版本、用户页面计划、导入内容、本地资产绑定、阶段状态、验证报告和输出哈希。

UI 字段显示名可修改，底层稳定 key 不随显示名变更；AI 使用内部 key 和说明。用户选择新页序后，重新导出对应 Schema。第一版同一源页不多次实例化，避免增加实例级内容命名和绑定复杂度。

### 7.2 导出包

| 文件或目录 | 用途 |
| --- | --- |
| `template.pptx` | 保留 DSL 的已发布准备模板；最终生成 PPTX 与它区分 |
| `template-manifest.json` | 完整 locator、组件和列表合同，不交给 AI 随意修改 |
| `deck-content.schema.json` | 外部 AI 内容草稿合同 |
| `input.schema.json` | 资源绑定后的最终输入合同 |
| `template.lock.json`、`template-lint.json` | 版本、哈希与编译结果 |
| `instructions.zh.md`、`instructions.en.md` | AI 使用步骤、生成步骤、限制和局部修复方式 |
| `content.example.json`、`page-plan.json` | 经去敏的合法内容示例和冻结页面计划 |
| `runtime/` | 锁定版本的可运行分发物、依赖锁与许可说明；无需产品账号 |

不把整份 Skill、历史模板、原客户样例和绝对机器路径无筛选打包。导出包是可迁移能力的验收对象，不仅是下载几个 JSON。

独立流程与网页共用同一运行库：内容校验 → 绑定用户本地资产 → 最终校验 → 生成 → verify。第一次安装依赖可需要网络；安装后使用已有内容和资产生成不依赖产品服务、AI API 或账号。

## 8. 质量、安全与可观测性

### 8.1 质量层次

- **结构校验**：字段、长度、列表、版本、OOXML relationships、媒体和动画引用。
- **模板试填**：正常、最长文本、最少/最多列表项及两种内容语言；只测试模板声明支持的语言。
- **视觉检查**：预览检查错位和缺字，提示字体缺失与渲染器差异。
- **原生验收**：对最终精确文件检查无修复提示、固定内容保留和文本/图片可编辑。数据组件启用前另做工作簿对账。

P0 通过字符容量、几何越界提示、边界试填与人工确认检查排版。超限时要求修改内容或合同，保持文本框与字号规则。完整自动视觉溢出识别后置。

M0 先用三份真实模板验证预览与原生对象映射，再确定渲染方案、工作量、依赖体积和许可成本。大型第三方依赖须单独确认。

### 8.2 文件与数据边界

文件解包限制大小、压缩比和 entry 数，拒绝路径穿越；不执行宏、不自动访问外部关系。资产路径限制在用户选择的工作目录内，AI JSON 无权读取任意本地文件。

导出给外部 AI 的提示词与样例默认去敏，并展示实际导出内容。P0 无内置第三方推理；后续 AI 建议需说明发送范围、供应商与费用。

### 8.3 日志和指标

记录 `workspaceId/templateVersion/jobId/stage`、runtime 版本、耗时与错误 code。Debug 记录节点映射与验证过程，Info 记录编译/发布/生成开始及结果，Warn 记录字体缺失、兼容风险和可恢复失败，Error 记录阻断失败与异常堆栈。所有异常向 UI 和任务报告传播，不吞错。

默认日志不写正文、图片、完整本地路径和客户样例；诊断包由用户查看后导出。首版指标保存在本地，不默认上传遥测。

后续统一追踪预留：导入→预览→打标→编译→试填→生成→verify 的 span；记录首次配置耗时、字段修正次数、编译失败率、生成成功率、再次生成次数及人工修订时间。统计带模板类型和失败分类。

## 9. 发布验收场景

| 场景 | 预期 |
| --- | --- |
| 仅两页、无目录的客户模板 | template-fill 编译和生成成功；structured 原规则继续生效 |
| 文本与图片替换 | 只变更确认对象，固定内容保留，图片按框裁剪 |
| 同模板两次内容生成 | 第二次无需重新标记，不复用上次正文或错误资产 |
| 中文短标题和英文连续长文本 | 合同按可见字符执行；发现视觉风险后允许修改合同并重试填 |
| 变长列表最少/最多项 | 同构组件完整、布局符合预制区域，无悬空动画引用 |
| Group 不同构或 Item 识别歧义 | 阻断发布并定位对象，不静默把对象当普通文本 |
| 缺字段、额外字段、超长、缺图片 | 精确报错；不生成正式结果，不自动截断或猜值 |
| 原稿含备注、字体缺失或外部链接 | 导入报告明确影响；按兼容策略确认或阻断 |
| 用旧 Manifest 搭配新 PPTX | 哈希校验失败；不得覆盖旧版本或自动降级 |
| 用户在全新环境使用导出包 | 安装后不连产品服务也可完成校验、生成和 verify |
| 生成中断、预览失败、旧结果存在 | 状态可恢复；不能展示旧结果为本次成功文件 |

测试重点是输入输出合同、复杂 OOXML 回归和真实用户闭环；不为可逆文案或简单 UI 结构添加镜像实现的测试。

## 11. 风险和待确认事项

1. 目标用户是否愿意投入一次配置，还是希望直接代做；对可迁移性的需求是否真实影响购买。
2. 首批模板中不支持对象、散落列表和复杂混排的比例；是否需要调整组件优先级。
3. 预览渲染方案、字体许可、依赖体积和运行环境；在 M0 定案。
4. 两期内容节省的时间能否覆盖配置和维护成本；需记录基线与修订时间。
5. 独立生成器的分发许可、升级方式与依赖安装体验；逐项核验依赖许可。
6. 本地产品的安装与使用门槛是否适合目标用户；需要网页托管时另立账号、隔离和存储需求。
