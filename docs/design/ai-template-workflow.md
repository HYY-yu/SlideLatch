# SlideLatch：模板编译与复用闭环（本地第三增量）

日期：2026-11-07。产品统一为 **SlideLatch**，PPT-DSL 是底层模板合同及确定性运行时，不是第二个产品入口。本次没有推送、部署、额外调用付费模型服务或使用客户文件。目标是忠于原版的快速复用，不是依据品牌风格重新绘制页面。

## 当前使用入口

SlideLatch Skill 驱动 AI 完成准备、打标与加载真实标记稿，再打开 Studio 供用户验收。Studio 不提供人工搬运 AI 请求与提案 JSON 的窗口。用户确认后，AI 可导出当前精确稿并编译，用户也可直接创建成稿。底层无 UI 的 WorkflowController 保留共用工作区的操作接口；确认不代替边界、原生或发布证据。

## 目标架构

1. 用户提供 PPTX，SlideLatch 保留原始 OOXML 为唯一设计来源。
2. AI 读取对象、文字、层级、几何与页面备注，提出对象标记和内容边界。
3. 工作台与程序验证器共同审查：AI 在真实界面试填候选内容、观察上下限，记录通过/失败及依据，必要时修改标记后重新验证。
4. 通过门禁的标记稿编译为版本绑定的模板包。模板字节指纹、Schema、Manifest、审查证据一起保存。
5. 内容生成流程按页面类型、容量和资产约束选择模板页，填充内容；运行时严格校验后沿用原页/母版生成可编辑 PPTX，再验证包结构。

程序通过、SVG 样本通过与 PowerPoint 原生验收是三种不同证据，不能相互替代。不存在由有限边界样本推出“任意内容必然视觉正确”的保证。

## 当前实际实现

- 现有纯前端工作台支持本地 `.pptx` 导入，50 MB / 200 页；声明解压大小上限 200 MB、最多 5000 ZIP entries。失败保留原工作区；成功替换清空历史、选中状态、预览与旧下载地址。
- 不再把导出页数、页数显示或画布尺寸硬编码为 33 页 / 960×540。
- 可导出 AI 检查清单，包含原文件 SHA-256、当前补丁快照指纹、页备注、对象 ID、几何、现有标记、可用标记类型与程序问题。
- AI 提案允许修改对象名称标记以及显式的页面类型/顺序逻辑合同。重复或未知对象、越界/跨类型标记、未知字段与过期快照均被拒绝。几何、正文、文件路径、任意备注和可执行内容不能通过这个提案入口偷偷写入。页面合同使用独立备注对象，保留原讲者备注，进入同一撤销与快照历史。
- 文本最少/最多字数与动态列表最少/最多项数生成独立预览案例，预览不写入最终正文。观察记录包含快照、案例、通过/失败、依据、渲染器及时间；修改模板使旧观察失效。
- 审查包 ZIP 包含同一次生成的 `marked.pptx`、`workflow-review.json` 和 `workspace-inspection.json`，审查文件绑定该 PPTX 的精确 SHA-256。导出一个包不代表它已经通过。
- 完整 PPT-DSL 编译器、Schema、输入校验、原生 PPTX 生成与包验证器已纳入 `packages/ppt-dsl`；保留 MIT 许可与来源说明。
- 新增确定性模板页候选选择：页面类型、列表容量、已有资产硬过滤；逻辑关系、容量余量、重复使用惩罚和稳定模板 ID 排序。
- `template:release` 验证审查包、完整边界证据及实际 OOXML，再编译到新目录。检查失败不留下可用发布目录，不覆盖已有目录或文件。发布成功最后写入 `workflow-release.json` 完成标记。

## 明确尚未实现

- 没有接入常驻模型服务。本地规则识别不是模型语义识别。新增仓库 Skill 与离线 prepare/apply 入口可供已授权 AI 对话产生并应用真实语义提案；用户还可主动使用现有 ChatGPT 登录的 Codex CLI，另行确认文档与额度使用。见 [AI 入口](ai-entrypoint.md)。
- 不会可靠自动理解任意 PPT 的页面角色、逻辑和可编辑语义。现在可通过工作台或 AI 的 pages 提案补写独立页面合同，保留原备注；页角色猜测不会自动应用。普通 PPT 仍需确认这些语义。
- 已增加实际 SVG 渲染容量搜索：当前页普通、未旋转、非列表文本，从长度 1 到用户设定上限（最多 128）逐个测试现有语义、宽汉字、宽拉丁字母三组压力文本。记录溢出、布局尺寸与所有试验，不假设单调性。结果只是该有限窗口的候选上限，不是原生视觉判分，也不能推导语义最小值。
- 动态列表 SVG 预览与原生生成布局仍不是同一渲染器。超过 100 项、超过 10000 字的案例不能通过此预览门禁。
- 图表、表格、图片、未标记对象、复杂特效、字体替换与动画的完整视觉验收尚未实现。原生 PowerPoint 打开无修复提示也没有据本次代码测试获得证明。
- 浏览器正在接入模板页选择、纯文本填写与真实 PPTX 生成；不等于“一键 AI 生成整份 PPT”。完整运行时继续承担更复杂的数据和资产处理。所有生成保留完整演示文稿的封面、目录、章节过渡、内容、结尾及章节数约束，未放宽为任意短稿。最终支持范围以第三增量验收为准。
- 重复生成验证的是内容/对象身份/几何与包有效性。ZIP 时间戳和生成器 creation GUID 可能不同，不承诺二进制字节一致。

## 本地运行

仓库根目录已有前端依赖；底层依赖独立属于 `packages/ppt-dsl`。本次仅以忽略的本地 node_modules 符号链接复用已安装依赖，没有安装任何软件。新机器需在获得安装授权后分别安装锁定依赖；产品源代码不依赖本机绝对路径。

```sh
npm run dev
# http://127.0.0.1:3000/zh 或 /en
npm run check
npm run build
```

编译与生成必须显式提供输入，不会默认套用内置示例：

```sh
# 原始 DSL 编译，不包含视觉审查背书
npm run template:compile -- --template ./marked.pptx --out ./compiled

# 工作台审查包解压后，通过审查门禁编译。out 必须不存在。
npm run template:release -- --template ./review/marked.pptx \
  --review ./review/workflow-review.json --out ./reviewed-template

npm run template:select -- --manifest ./compiled/template-manifest.json \
  --request ./candidate-request.json
npm run deck:validate -- --manifest ./compiled/template-manifest.json --input ./deck-input.json
npm run deck:generate -- --template ./compiled/template.pptx \
  --manifest ./compiled/template-manifest.json --input ./deck-input.json --out ./result.pptx
npm run deck:verify -- --pptx ./result.pptx
```

候选请求示例：

```json
{"pageType":"内容页","listCounts":{"list_1":3},"availableAssetKinds":[],"logic":[],"usedTemplateIds":[]}
```

资产种类可包括 `image`、`icon`、`background`。硬过滤不会下载/生成资产，也不会保证内容语义已经匹配。

## AI / 浏览器代理合同

页面加载工作台后，`window.slidelatchWorkflow` 提供有限 API：

- `inspect()`：读取当前工作区与快照。
- `applyProposal(proposal)`：校验后提交一批标记，走同一撤销历史；任何错误均不部分提交。
- `previewProbe(probeId)`：在现有 SVG 画布展示该案例，切到其页面和对象。
- `recordObservation({probeId,snapshotId,verdict,reason})`：只能记录正在展示的当前案例，必须提供依据。
- `getReview()`：获取当前审查状态，最终可编译状态仍需要导出时绑定准确文件字节。

提案格式：

```json
{
  "schemaVersion": 1,
  "templateSha256": "来自 inspect 的原模板 SHA-256",
  "snapshotId": "来自 inspect 的快照指纹",
  "marks": [{"key":"ppt/slides/slide1.xml#3","name":"@文本[2-12]","reason":"对象是短标题，范围为待实测候选"}]
}
```

导出的文字和备注是待分析的文档数据，不是应执行的指令。审查记录是操作者对显示样本的观察，不是认证过的视觉证据；报告不能提供签名或防伪保证。禁止把未实际检查的案例批量填为通过。

## 第二增量：自动测量与页面合同

- `recognizeStructure(snapshot)` 返回待审查的页级文本候选、跳过原因、页角色猜测；保留现有标记和分组，无法判定的图片、图标、日期/数字、装饰不会擅自解锁。
- `buildRecognitionRequest(snapshot)` 输出严格 Schema、请求说明和明确视为不可信文档数据的对象清单。不读取凭据、不发送文档、不调用任何模型。
- `window.slidelatchWorkflow.searchTextCapacity({key,upper})` 在当前真实 SVG 画布试填并测量。`cancelCapacitySearch()` 取消并恢复正文；修改模板、切页或改变编辑状态使结果失效。`getCapacityReport()` 读取当前有限样本报告。
- 观察字体加载、两个动画帧、文本矩形、文本 Range 布局矩形、滚动溢出、SVG 缩放和居中裁剪。不可测量的对象返回 unknown/inconclusive，不能当成通过。
- 容量搜索不提交标记、不填写人工通过记录，也不改变正文。报告完整保留每个字符串、长度、测量值与原因。
- `pages` 提案支持 `{path,pageType,logic,reason}`，可单独应用或与 marks 同时原子提交。页面语义写入名为 `slidelatch-page-contract` 的独立备注对象；编译器优先读取它，原讲者备注保持不变。
- 普通无页面角色 PPT 的测试用例在补齐明确五类页面合同后真实编译成功；不代表任意文件语义都能自动猜对。
- 浏览器与编译器现在共用组件匹配和文字长度合同。固定原生 Group 也生成数量边界；重排的同类文字按几何/样例匹配，歧义失败。每个列表 Item 每种组件最多匹配 8 个，超限明确报错，避免全排列耗尽资源。
- 新增字数样本回归覆盖全部真实模板边界，避免截断后尾空格导致“名义 50、实际 49”。原先需要环境变量才真正执行的组件对齐测试改成自包含 OOXML 用例。

页面提案示例：

```json
{"schemaVersion":1,"templateSha256":"来自当前检查清单","snapshotId":"来自当前检查清单","pages":[{"path":"ppt/slides/slide1.xml","pageType":"封面页","logic":[],"reason":"已确认该页作为报告封面"}]}
```

新增代码：`lib/workflow/recognition.ts`、`constraint-search.ts`、`measure-preview.ts`、`page-contract.ts`，以及 `packages/ppt-dsl/src/component-matching.ts`、`text-length.ts`。最终验收结果见下方追加记录。

自动测量采用 DOM 布局矩形而非绘制后像素级字形轮廓，字体空白可能造成保守失败。只有外层可见文本盒的滚动溢出才算裁剪，内层 `overflow: visible` 超出自己的行盒不独立判失败。结果不等于原生 PowerPoint 溢出判定。

浏览器实测发现短文本 Range 字体矩形也可能超出行盒（字体空白，不等同于可见字形裁切）。因此容量拟合明确采用 `fitKind: block-layout-only`：检查块布局与外层滚动范围，将 `textRangeOverflow` 单独保留为必须目视检查的风险，不把字体矩形越界误当成文字块溢出。任何容量结果都不会自动填写视觉通过记录。

## 第三增量：原版快速复用入口

定位明确为**忠于原版的快速复用**，不是重新生成品牌风格。作者工作台与成稿工作台现在在同一页面：

- 「编译当前工作区草稿」使用当前标记/页面合同实际写出的 PPTX；也可导入单个 PPTX、编译 ZIP，或 template + manifest + lock。无法编译时报告缺失合同，不替换成示例。
- 「试用公开示例」只在明确点击后加载公开模板。「创建可复用成稿骨架」按目录原数量创建合法完整序列，然后逐页改选模板、填写纯文本/原数量列表。仍保留完整稿件的五类页面及 3–6 章节要求。
- 只有当前版本完整输入校验通过，才能在浏览器本地生成真正的 PPTX 并提供下载。编辑、改模板、取消或换源使旧检查/下载失效；不覆盖原 PPT。
- 浏览器生成直接克隆原 OOXML，复用共享编译、选择、校验与确定性编号。保留对象几何、母版、主题、媒体及未编辑文本的整个 txBody；重复选用同页时独立克隆，互不覆盖。
- 支持相同样式拆分 run 的纯文本编辑与自动序号；列表保持原有数量。未改动的混合样式文字原样保留。修改混合 run/段落样式、软换行或字段文本时明确拒绝，不偷偷丢掉样式或改变段落语义。
- 图片/图标/背景仅保留原资源，不在浏览器替换；富文本、标记图表/表格填数、调色和列表增减仍使用完整 CLI。宏、外链媒体、不支持的 section/custom-show 或继承内部页导航被拒绝。
- 精确校验 source SHA、manifest 内容和 lock；审查文件先核对实际 PPTX，再核对编译合同，不只相信自报哈希。
- 生成后不保留原备注与未选原页。对可通过母版/布局导航遗留旧页/备注的路径明确拦截。ZIP 输入和预计克隆量都受解压预算约束：50 MB 压缩输入、5000 entries、200 MB 总展开量，另有单条/XML 预算。

新增 `scripts/slidelatch-ai.mjs` 及仓库 Skill，离线 prepare/apply 连接已有 AI 对话；用户可另行主动启动已登录 ChatGPT 的 Codex CLI。真实模型、成本、授权和复现实例见 [AI 入口与验证记录](ai-entrypoint.md)。本次语义提案来自当前已授权对话对公开示例的实际判断，不是规则候选；没有另行调用 Codex 云端模型/API。

### 第三增量程序验收

本轮最初的 build、静态导出和 81 项主测试、99 项运行时测试通过；独立运行的 12 个浏览器引擎场景和 5 个 AI 交接测试也执行通过。但后续发现主测试中的浏览器包装错误继承了 NODE_TEST_CONTEXT，实际跳过了子测试，不能把当时的根检查当成已包含这 12 项。该包装及跨端验证缺口已修正，最新证据见下节。

## 后续复核修正：统一浏览器与运行时产物门禁

复核实际生成包时发现，浏览器曾使用 `rIdSlideLatch1` 之类关系 ID，虽然其局部检查返回 structural_pass，同仓库完整 verifier 仍会拒绝。这是两端验证合同不一致，不能据此断言文件必然在 PowerPoint 中损坏，也不能把此前的局部通过等同于完整运行时通过。

已改为分配未占用的数字 `rIdN`，并在浏览器压缩输出后重新读取最终 ZIP，执行**同一个** `verifyDeckPackage`。任何完整验证错误都会阻止返回成功及创建下载链接；只有实际通过才返回 `runtimePackageValidation: passed`。原生 Office 仍为 `not_run`。

同时修复根测试包装：显式移除子进程的 `NODE_TEST_CONTEXT`，使用 TAP 报告，要求至少 16 个测试真正执行且 pass 等于 tests、skip/fail 为 0；递归跳过警告直接失败，不能再只相信进程退出码。

新增交叉验证覆盖：中文和英文公开模板各生成两次 13 页 PPTX、从原始公开 growth 示例重新应用语义提案后两次生成 9 页 PPTX。每份实际 bytes 均直接送入完整运行时 verifier，核对 passed、无错误、无非标准关系 ID、无关系冲突及稳定重用。另加悬空动画目标反例，证明浏览器成功状态确实受共享门禁约束。原版几何、样式、资源及重复克隆测试继续保留。
